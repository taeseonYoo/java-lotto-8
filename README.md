## 기능 요구사항

--- 

### 입력

- [x] 로또 구입 금액을 입력받는다.
  - 로또 구입 금액은 1,000원 단위로 입력 받는다.
  - 로또 구매 금액은 1,000이상의 int 범위의 정수를 입력 받는다.

- [x] 당첨 번호를 입력받는다.
  - 당첨 번호는 중복되지 않는 숫자 6개를 입력한다.
  - 당첨 번호는 1~45사이의 정수이다.
  - 당첨 번호는 쉼표(,)를 기준으로 구분한다.

- [x] 보너스 번호를 입력 받는다.
  - 보너스 번호는 당첨 번호와 중복되지 않는 숫자 1개를 입력한다.
  - 보너스 번호는 1~45사이의 정수이다.


### 로또

- [x] 로또 수량 만큼 로또 번호를 생성한다.
  - 로또 번호는 중복되지 않는 숫자 6개로 구성된다.
  - 로또 번호는 1~45사이의 정수이다.
- [x] 각 로또는 중복된 조합으로 구성될 수 있다. (ex. 2,000원 구매 시 [1, 2, 3, 4, 5, 6],[1, 2, 3, 4, 5, 6] 허용)

### 당첨
- [x] 당첨은 1등부터 5등까지 있다.
- [x] 당첨 기준과 금액은 다음과 같다.
  - 1등: 6개 번호 일치 / 2,000,000,000원
  - 2등: 5개 번호 + 보너스 번호 일치 / 30,000,000원
  - 3등: 5개 번호 일치 / 1,500,000원
  - 4등: 4개 번호 일치 / 50,000원
  - 5등: 3개 번호 일치 / 5,000원

### 출력

- [x] 구입 금액 입력 안내 메세지를 출력한다.
~~~
구입 금액을 입력해 주세요.
~~~
- [x] 발행한 로또 수량을 출력한다.
~~~
8개를 구매했습니다.
~~~
- [x] 발행한 로또 번호를 오름차순으로 출력한다.
~~~
[8, 21, 23, 41, 42, 43] 
[3, 5, 11, 16, 32, 38] 
[7, 11, 16, 35, 36, 44] 
[1, 8, 11, 31, 41, 42] 
[13, 14, 16, 38, 42, 45] 
[7, 11, 30, 40, 42, 43] 
[2, 13, 22, 32, 38, 45] 
[1, 3, 5, 14, 22, 45]
~~~
- [x] 당첨 내역을 출력한다.
  - 당첨 금액은 천 단위 구분 기호를 사용하여 출력한다.
~~~
3개 일치 (5,000원) - 1개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
6개 일치 (2,000,000,000원) - 0개
~~~
- [ ] 수익률은 소수점 둘째 자리에서 반올림하여 출력한다. 
  - 수익률이 1000 이상이라면, 천 단위 구분 기호를 사용한다.(ex. 1,000,000.0%)
~~~
총 수익률은 62.5%입니다.
~~~
- [x] 예외 상황 시 에러 문구를 출력해야 한다.
    - 에러 문구는 [ERROR]로 시작해야 한다.
~~~
[ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.
~~~


### 예외 조건

> 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시키고, "[ERROR]"로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.

- [x] 로또 구입 금액이 숫자가 아닌 문자가 입력되는 경우
- [x] 로또 구입 금액이 int 범위의 정수보다 큰 수가 입력되는 경우
- [x] 로또 구입 금액이 1,000원으로 나누어 떨어지지 않는 경우

- [x] 당첨 번호가 숫자와 (,)쉼표가 아닌 문자가 입력되는 경우
- [x] 당첨 번호가 int 범위의 정수보다 큰 수가 입력되는 경우
- [x] 당첨 번호가 1~45사이의 정수가 주어지지 않는 경우
- [x] 당첨 번호가 정확히 6개가 주어지지 않은 경우
- [x] 당첨 번호에 중복된 숫자가 입력되는 경우 (ex. [1,1,2,3,4,5] )

- [x] 보너스 번호가 숫자가 아닌 문자가 입력되는 경우
- [x] 보너스 번호가 int 범위의 정수보다 큰 수가 입력되는 경우
- [x] 보너스 번호가 1~45사이의 정수가 주어지지 않는 경우
- [x] 보너스 번호가 당첨 번호와 일치하는 경우


## 프로그래밍 요구 사항 1

---
- JDK 21 버전에서 실행 가능해야 한다.
- 프로그램 실행의 시작점은 Application의 main()이다.
- build.gradle 파일은 변경할 수 없으며, 제공된 라이브러리 이외의 외부 라이브러리는 사용하지 않는다.
- 프로그램 종료 시 System.exit()를 호출하지 않는다.
- 프로그래밍 요구 사항에서 달리 명시하지 않는 한 파일, 패키지 등의 이름을 바꾸거나 이동하지 않는다.
- 자바 코드 컨벤션을 지키면서 프로그래밍한다.
- 기본적으로 Java Style Guide를 원칙으로 한다.

## 프로그래밍 요구 사항 2

---
- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다. 
  - 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- 3항 연산자를 쓰지 않는다.
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
  - 테스트 도구 사용법이 익숙하지 않다면 아래 문서를 참고하여 학습한 후 테스트를 구현한다.

## 프로그래밍 요구 사항 3

--- 
- 함수(또는 메서드)의 길이가 15라인을 넘어가지 않도록 구현한다.
  - 함수(또는 메서드)가 한 가지 일만 잘 하도록 구현한다.
- else 예약어를 쓰지 않는다.
  - else를 쓰지 말라고 하니 switch/case로 구현하는 경우가 있는데 switch/case도 허용하지 않는다. 
  - 힌트: if 조건절에서 값을 return하는 방식으로 구현하면 else를 사용하지 않아도 된다.
- Java Enum을 적용하여 프로그램을 구현한다. 
- 구현한 기능에 대한 단위 테스트를 작성한다. 단, UI(System.out, System.in, Scanner) 로직은 제외한다. 
  - 단위 테스트 작성이 익숙하지 않다면 LottoTest를 참고하여 학습한 후 테스트를 작성한다.

## 라이브러리
- camp.nextstep.edu.missionutils에서 제공하는 Randoms 및 Console API를 사용하여 구현해야 한다.
  - Random 값 추출은 camp.nextstep.edu.missionutils.Randoms의 pickUniqueNumbersInRange()를 활용한다.
  - 사용자가 입력하는 값은 camp.nextstep.edu.missionutils.Console의 readLine()을 활용한다.
